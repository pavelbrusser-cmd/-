# Отмена личных событий Mail.ru

Пользователь согласовал отмену личных событий Mail.ru через удаление
с сохранением копии в сервисе. Для повторяющейся серии отменяется только
выбранный экземпляр. Это новая функция: её развёртывание и проверка
на действующем Render-сервисе ещё предстоят.

Сервис уже размещён, чтение четырёх аккаунтов проверено. После исправления
потребления памяти полный сбор на 15 октября 2026 года завершился успешно:
35 событий из 11 календарей. Пользователь также проверил перенос личного
тестового события первого аккаунта Mail.ru с 15:00 на 16:00. Эти результаты
не являются проверкой новой отмены.

## Что происходит при отмене

Mail.ru не сохраняет `STATUS=CANCELLED` надёжно. Для личной записи без участников
используется следующий порядок:

1. Страница действия заново читает событие, проверяет его версию и права.
   Перед подтверждением она сообщает об удалении и сохранении копии.
2. После подтверждения владельцем сервис сохраняет исходную запись iCalendar
   и данные отменяемого события в архиве SQLite. Эта копия пока ожидает
   подтверждения результата и не попадает в дайджест.
3. Обычное одиночное событие удаляется условным `DELETE` с `If-Match`.
   Для серии выполняется `PUT`: в основную запись добавляется `EXDATE`
   исходного слота, а точное исключение выбранного экземпляра, если оно есть,
   удаляется. Основная серия и остальные повторения сохраняются.
4. Сервис проверяет результат: после успешного удаления ресурс должен вернуть
   `404`, а после изменения серии выбранное повторение должно отсутствовать
   при сохранении остальных данных.
5. Только подтверждённый результат переводит действие в `done`. Новый сбор
   добавляет архивную запись в дайджест подходящего дня с пометкой «Отменено»
   (`CANCELLED`) и без кнопок действий.

У перенесённого повторения исключается исходный `RECURRENCE-ID`, чтобы после
удаления изменённой версии не появилось старое время. Архив сохраняет известные
даты и время отменённого экземпляра. Если событие позже восстановлено
в календаре с той же идентичностью, актуальная запись имеет приоритет
перед архивной отметкой.

## Границы операции

Удаление с архивом доступно личным событиям без `ATTENDEE`. При наличии участников
эта ветка отказывается от операции. Неоднозначная серия, несколько основных
записей или отдельное исключение без доступной основной серии также не удаляются.
Отмена всей серии через эту кнопку не выполняется.

Отклонение приглашения участником — отдельная операция: меняется собственный
`PARTSTAT=DECLINED`. Оно не означает отмену встречи для всех и не использует
удаление личного события. Доставка ответов другим участникам этой функцией
не подтверждается.

При конфликте версии, отказе сервера или неопределённом результате операция
не повторяется автоматически. Архивные копии действий со статусом `running`,
`failed` или `uncertain` не отображаются как подтверждённые отмены. Если сервис
сообщил о неизвестном результате, сначала нужно проверить календарь;
повторное нажатие или новая ссылка не заменяют эту проверку.

## Где хранится копия

Архив находится в той же `actions.sqlite3`, что и ссылки действий. На Render
это постоянный диск `/var/data`, выбранный через `DIGEST_STATE_DIR`.
Подготовка письма, веб-сервис и последующий сбор используют эту общую базу.
Новый `preview` не заменяет и не очищает архив отмен.

Резервная копия содержит исходные календарные данные, включая личные сведения.
Она хранится в приватной базе с правами `0600`, вне Git и общих журналов.
Дайджест читает только компактную запись подтверждённой отмены, без загрузки
полной резервной копии. Диск и база должны сохраняться между развёртываниями.
Автоматическое восстановление события из архива в этой версии не реализовано.

## Проверка на уже подготовленном тестовом событии

Проходите по одному пункту и переходите к следующему после успешного результата.
Пароль сервиса, содержимое письма и ссылки с токенами остаются во внешнем окне
браузера; в чат достаточно сообщать состояние шага.

1. В GitHub объедините pull request этой функции с `main`. В Render откройте
   существующий сервис и выберите **Manual Deploy → Deploy latest commit**.
   Дождитесь **Live** и проверьте `/health`.
2. Откройте Shell этого сервиса и сформируйте свежий дайджест:

   ```sh
   .venv/bin/calendar-digest preview --date 2026-10-15 --directory /var/data
   ```

3. После успешного завершения выпустите новые ссылки:

   ```sh
   .venv/bin/calendar-digest issue-actions --date 2026-10-15 --directory /var/data
   ```

4. Откройте новое письмо привычным способом. Для локального HTML выведите файл
   в своём Render Shell, скопируйте HTML в текстовый редактор и сохраните
   как файл `.html` в UTF-8:

   ```sh
   cat /var/data/email-actions-2026-10-15.html
   ```

5. Найдите именно личное тестовое событие первого аккаунта Mail.ru на
   **15 октября, 16:00 по Москве**, ранее перенесённое с 15:00. Проверьте
   название, календарь и отсутствие участников. Откройте «Отменить», войдите
   в сервис и убедитесь, что форма объясняет удаление из Mail.ru с сохранением
   копии. Подтвердите отмену этого тестового события.
6. После сообщения об успешной отмене проверьте в Mail.ru, что тестовое
   событие исчезло. При ошибке или неизвестном результате сначала разберите
   состояние календаря, не повторяя действие.
7. Снова выполните команду `preview` из пункта 2. Затем повторите `issue-actions`
   из пункта 3 и откройте обновлённый HTML из пункта 4. Тестовое событие должно
   присутствовать как **«Отменено»**, со временем 16:00 и без кнопок.

Это проверяет отмену одиночного события. Исключение повторения нужно отдельно
проверить на тестовой серии: выбранный экземпляр отсутствует, соседние
повторения сохранены, отмена видна в дайджесте соответствующего дня.
Расписание и отправка писем остаются отдельным этапом.
