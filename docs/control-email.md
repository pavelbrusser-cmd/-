# Письма исполнителям контрольных поручений

Сервис планирует отдельное письмо каждому подходящему участнику события из подключённого контрольного аккаунта `gpb.control@mail.ru` (Mail.ru · 2). В расчёт входят все его календари с событиями. Собственные адреса владельца, участники с ответом «Отклонено», переговорные и другие ресурсы исключаются. Получатели берутся из поля участников календаря; адреса из описания или названия не используются. Явно указанный адрес группы и участник, делегировавший участие, остаются получателями, если не относятся к исключениям.

Обычное поручение получает напоминания за **3 дня**, за **1 день** и за **1 час**. Для событий на весь день последнее напоминание приходит в день события в 09:00 МСК. Дополнительное раннее напоминание определяется отдельным словом в названии, без учёта регистра:

| Слово в названии | Дополнительный срок |
| --- | --- |
| `daily` | Только обычные напоминания |
| `weekly` | За 7 дней |
| `biweekly` | За 14 дней |
| `monthly` | За 1 календарный месяц |
| `bimonthly` | За 2 календарных месяца |
| `quarterly` | За 3 календарных месяца |
| `semiannually` | За 6 календарных месяцев |
| `yearly`, `annually` | За 1 календарный год |
| `biennially` | За 2 календарных года |

Сроки за дни, недели, месяцы и годы назначаются на **09:00 МСК**. Часовое напоминание рассчитывается от фактического начала события. Время между 00:00 и 06:59 переносится на **07:00 того же московского дня**, в том числе для раннего события, которое к этому моменту уже началось. В предпросмотре и письме такой перенос обозначен явно. Календарный месяц учитывает его длину: если соответствующего числа нет, используется последний день месяца. Совпавшие напоминания одному получателю об одном экземпляре события объединяются в одно письмо.

Отмена, перенос, ответ участника и изменение его адреса учитываются после успешного обновления контрольных календарей. Повторяющиеся события рассматриваются по отдельным экземплярам. Личные push-уведомления и ежедневный дайджест продолжают использовать свои действующие правила и независимые журналы.

## Оформление и отправитель

Тема каждого письма:

> ВНИМАНИЕ! Контроль и мониторинг поручений!

Письмо содержит читаемый текст и HTML с красным восклицательным знаком, названием поручения, сроком, календарём и местом, если оно задано. Заголовки `Importance: high`, `X-Priority: 1 (Highest)` и `X-MSMail-Priority: High` обозначают высокую важность; вид значка в списке писем зависит от почтового приложения получателя.

[Образец письма на вымышленных данных](examples/control-email-preview.html).

Для доставки используется уже настроенный SMTP-отправитель. У каждого письма один получатель: адреса других участников ему не раскрываются. Сохранение ответа или действий в календаре через такое письмо не предусмотрено.

## Проверка на Render

Новая настройка `CONTROL_EMAIL_ENABLED` по умолчанию равна `false`. При установке обновления запланированная отправка остаётся выключенной, пока значение не изменено в Render.

1. После обновления со статусом Live откройте новую вкладку **Shell** и сформируйте приватный предпросмотр следующих семи дней:

   ```bash
   .venv/bin/calendar-digest preview-control-email --days 7 --directory /var/data
   ```

   Команда читает контрольный аккаунт и сохраняет JSON и HTML с адресами получателей. В консоль выводятся только даты, счётчики и пути. SMTP не вызывается, очередь отправок не изменяется, расписание не включается.

   При необходимости можно указать первый день через `--date YYYY-MM-DD` или `--start-date YYYY-MM-DD`. Прошедшие часы исключаются; граница рассчитывается повторно после чтения календаря. Максимальный период — 31 день.

2. Откройте созданный `control-email-preview-YYYY-MM-DD.html` у себя локально тем же способом, что и образец дайджеста. Проверьте карточки с временем отправки, сроком поручения и фактическим получателем. Файлы содержат частные данные: оставьте их в своём браузере и не публикуйте в репозитории или чате.

3. Для предварительного заполнения независимой очереди выполните:

   ```bash
   .venv/bin/calendar-digest prepare-control-email --directory /var/data
   ```

   Это обновляет только кэш контрольных календарей и очередь будущих писем. Команда не активирует расписание и не отправляет сообщения.

4. Для запуска согласованных писем установите в **Render → Environment** значение `CONTROL_EMAIL_ENABLED=true` и примените изменения с развёртыванием сервиса. Остальные настройки расписаний сохраняются.

5. После статуса Live проверьте состояние:

   ```bash
   .venv/bin/calendar-digest control-email-status --directory /var/data
   ```

   Результат содержит признак включения, состояние отдельного процесса, время его работы и безопасные счётчики очереди. Имена и адреса получателей не выводятся. `control-email-cycle` — внутренняя команда процесса; запускать её вручную для обычной эксплуатации не нужно.

Чтобы остановить автоматические письма, установите `CONTROL_EMAIL_ENABLED=false` и примените изменение в Render. Это управление не отключает ежедневный дайджест или личные push-уведомления.

## Восстановление и защита от повторов

При первом включении отправляются только уведомления, срок которых наступает после активации. Исторические напоминания не догоняются. После кратковременного сбоя допустим повтор безопасно не принятого письма в пределах 15 минут от запланированного времени; более старое письмо пропускается.

Перед SMTP DATA состояние сохраняется на постоянном диске. Письмо со статусом `accepted` уже принято почтовым сервером. Статус `uncertain` означает, что результат передачи неизвестен: автоматический повтор запрещён, чтобы не отправить дубль. Принятие сервером не гарантирует появления во входящих — письмо также может оказаться в спаме или быть отклонено позднее.

Данные контрольной очереди хранятся отдельно от дайджеста и push на постоянном диске `/var/data`. Предпросмотры имеют права `0600`. Изменение каталога хранения или удаление журнала может лишить сервис информации об уже отправленных письмах; журнал следует сохранять между развёртываниями.
