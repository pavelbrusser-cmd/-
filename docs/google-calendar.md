# Отдельный источник Google Календаря

Сервис поддерживает основной календарь одного аккаунта Google. Это отдельный
источник `google`, а не поиск приглашений Gmail в iCloud/Mail.ru. Подписные и
дополнительные календари Google, Google Contacts и почта Gmail не читаются.

## Поведение

Дайджест использует те же правила отбора, что и для существующих источников:
все ответы на приглашения, многодневные события, повторения и известные
переносы. Google получает только разрешение
`https://www.googleapis.com/auth/calendar.readonly`; кнопки изменения событий
Google не выпускаются. Другие провайдеры сохраняют свои действия.

Обычные события Google создают push за один день в 09:00 МСК и за час до
начала. Для события на весь день последнее напоминание — в 09:00 того же дня.
Дни рождения имеют приоритет и сохраняют D−3/D−1/D0 в 09:00. Отменённые
события исключаются из push. Все ответы на приглашения включены. После переноса
очередь использует актуальное время; принятый провайдером push не отправляется
повторно. Постоянное ограничение 07:00 применяется ко всем новым уведомлениям.

Читаются полные наборы серий и исключений: `singleEvents=false`,
`showDeleted=true`, все страницы без фильтра по дате. Изменённое повторение
сохраняет исходный `RECURRENCE-ID`; местная зона повторяющегося мастера
сохраняется для переходов летнего времени. Google `eventType=birthday`
преобразуется в категорию дня рождения.

Google может возвращать удалённое событие только с ID, без названия и даты.
Такая запись не превращается в придуманное событие: она удаляется из активного
набора и очереди. Отменённые исключения с исходной датой сохраняются.
Для переноса отдельного события между чтениями необходим предыдущий снимок,
как и у остальных провайдеров. Совпадение названий между Google и другими
календарями не считается доказательством дубликата.

## Авторизация и постоянное хранение

Нужен OAuth-клиент Google типа «Веб-приложение» в проекте с включённым
Calendar API. У клиента должен быть зарегистрирован точный HTTPS URI:

```text
https://<домен-сервиса>/settings/google/callback
```

Адрес строится из `DIGEST_PUBLIC_URL` или `RENDER_EXTERNAL_URL`, а не из
заголовка HTTP Host. Страница `/settings/google` требует существующий пароль
сервиса, затем принимает Client ID, Client Secret и ожидаемый адрес аккаунта.
Эти данные вводятся только в защищённой странице; пароль самого Google
сервис не запрашивает. Вход и согласие происходят на `accounts.google.com`.

OAuth использует PKCE и одноразовый state с десятиминутным сроком и привязкой
к сессии владельца. После обмена кода проверяется ID основного календаря:
при выборе другого аккаунта подключение не активируется. Успешное подключение
автоматически включает источник. Старое подключение сохраняется, если новая
попытка завершается ошибкой или отказом Google.

Client Secret и offline refresh token хранятся в зашифрованном файле
`DIGEST_STATE_DIR/google/connection.enc` (0600, каталог 0700). Ключ выводится
из `DIGEST_ACTION_SECRET`; диск и этот секрет должны сохраняться между
деплоями. Смена секрета потребует повторного подключения Google. Токены не
записываются в cookie, Git или диагностический вывод.

Для длительной работы приложение Google не должно оставаться в режиме
External / Testing с ограниченным сроком refresh token: для Calendar scopes
в таком режиме Google обычно ограничивает его семью днями. Статус consent
screen и требования проверки задаются в Google Cloud, не этим сервисом.
Отозванный или истёкший доступ требует повторного согласия владельца.

Если подключение не завершилось, страница настроек показывает безопасный код
ошибки и действие для исправления. Основные случаи:

- `GOOGLE_CALENDAR_API_DISABLED`: включите Google Calendar API в том же
  проекте Google Cloud, где создан Client ID. Кнопка «Enable / Включить» на
  странице API означает, что API ещё отключён; у включённого API отображается
  «Manage / Управление».
- `GOOGLE_OAUTH_INVALID_CLIENT`: проверьте пару Client ID и Client Secret
  действующего OAuth-клиента типа «Веб-приложение».
- `GOOGLE_OAUTH_REDIRECT`: исправьте точный Authorized redirect URI у клиента.
- `GOOGLE_CALENDAR_SCOPE`: при новом входе разрешите чтение календарей.
- `GOOGLE_OAUTH_INVALID_GRANT` или `GOOGLE_OAUTH_RECONNECT`: начните новое
  подключение через настройки сервиса.
- `GOOGLE_OAUTH_RETRY` или `GOOGLE_CALENDAR_RETRY`: повторите попытку позже.

После исправления начинайте подключение заново кнопкой «Подключить через
Google»: обновление старой страницы callback не повторяет обмен одноразового
кода. Сообщения сервиса различают получение OAuth-разрешения и проверку
основного календаря; они не включают исходный ответ Google, токены, ссылки
из ошибок или идентификаторы проекта.

Альтернативная конфигурация для уже выданного offline grant — защищённые
переменные `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`,
`GOOGLE_CALENDAR_EMAIL` и `GOOGLE_CALENDAR_ENABLED=true`. Веб-подключению
эти переменные не требуются. Явное `GOOGLE_CALENDAR_ENABLED=false` выключает
источник даже при сохранённом подключении; не добавляйте этот override при
обычной настройке через страницу.

## Проверка и ограничения

`calendar-digest probe-google` проверяет аккаунт и полное чтение основного
календаря. Вывод содержит только результат, счётчики и `sent:false`.
`preview` и `preview-reminders` проверяют Google вместе с существующими
источниками, без отправки письма или push. Авторизация сама по себе не
отправляет проверочных сообщений, но после активации включённые планировщики
начнут учитывать источник.

При ошибке любого включённого источника общий снимок не заменяется частичным.
У Google пока используется полная ограниченная пагинация при каждом обновлении,
а не sync token. Стабильные ID и хеш содержимого сохраняют очередь при
неизменившихся данных. Общие ограничения коллектора (10 000 ресурсов и 30 MiB
ICS для календарей) продолжают действовать для суммы всех источников.

Проверки в репозитории используют искусственные ответы API: OAuth, права,
повторения, DST, переносы, отмены, очередь и оформление. Они не подтверждают
авторизацию конкретного Google аккаунта, реальную задержку чтения или установку
обновления на Render. Перед эксплуатацией нужна успешная реальная проверка;
для отправки push сохраняется существующий предел свежести наблюдения 120 секунд.

Официальные источники: [web server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server),
[сроки refresh token](https://developers.google.com/identity/protocols/oauth2#expiration),
[events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list),
[повторяющиеся события](https://developers.google.com/workspace/calendar/api/guides/recurringevents).
