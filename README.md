# Calendar Digest

Сервис календарного дайджеста из iCloud, трёх аккаунтов Mail.ru и отдельно
подключаемого Google Календаря.
Включает чтение CalDAV, подготовку HTML-письма и защищённые страницы
подтверждения, переноса и отмены событий с учётом возможностей провайдера.

## Размещение

Следуйте [пошаговой инструкции Render](docs/render-walkthrough.md).
Файл `render.yaml` задаёт один Python-сервис с постоянным диском.
Учётные данные вводятся в переменные окружения Render, не в исходники.

Сборка и автоматические проверки:

```sh
bash scripts/setup.sh
```

Данные календарей и база действий сохраняются в `DIGEST_STATE_DIR`;
на Render это `/var/data`. Для локальной разработки используется `.local/`,
исключённая из Git.

## Текущий этап

Веб-сервис действий работает на Render. Проверены чтение четырёх аккаунтов,
перенос и отмена личного события первого аккаунта Mail.ru; отменённое событие
удалено из календаря и сохранено в истории дайджеста без кнопок. Также проверено
принятие приглашения вторым аккаунтом Mail.ru: ответ виден организатору
в первом аккаунте. Эти проверки не распространяются на все действия всех провайдеров.

SMTP-отправка через Яндекс проверена настоящим письмом: владелец подтвердил
получение, оформление и работу кнопок. Ежедневная отправка в **17:00 по Москве**
одобрена 15 октября 2026 года. При диагностике 17 октября обнаружено выключенное
почтовое расписание; владелец повторно включил его в Render. Сбой подготовки
после изменения начала повторяющейся серии исправлен и обновление установлено:
проверочное письмо на 18 октября получено, оформление подтверждено.
Оба планировщика включены и имеют свежие отметки работы.
Для нового размещения расписание по умолчанию выключено; настройка и проверка
описаны в [email-delivery.md](docs/email-delivery.md).

Проверочное push-уведомление через Pushover получено и расшифровано на iPhone
15 октября 2026 года. Дни рождения из iCloud Contacts подключены на Render
через CardDAV; общий предпросмотр дней рождения и поручений одобрен владельцем.
Расписание push включено. Владелец подтвердил получение автоматических
уведомлений 16 октября и наличие всех шести утренних уведомлений 17 октября
в Pushover. Дополнительная проверка уведомления на iPhone также прошла.

Для автоматических push согласовано постоянное ограничение **не раньше 07:00
по Москве**: ночные напоминания переносятся на 07:00 того же дня, в том числе
для событий, начавшихся раньше. Уже запланированные ранние уведомления
обновляются с сохранением истории отправок. Дни рождения остаются в 09:00.

При проверке очереди обнаружено, что смена сервера iCloud заменяла идентификаторы
одних и тех же дней рождения. Исправление сохраняет идентичность адресной книги
и объединяет прежние записи с сохранением защиты от повторной отправки.
Исправление проверено на Render: прежние дубли в очереди устранены,
состояние принятых уведомлений сохраняется.

Для нового размещения источник контактов и автоматическая отправка по умолчанию
выключены (`ICLOUD_CONTACT_BIRTHDAYS_ENABLED=false`, `PUSH_SCHEDULE_ENABLED=false`).
Порядок проверки расписания, подготовки очереди и включения описан
в [push-notifications.md](docs/push-notifications.md). Настройка push сохраняет
действующее расписание почтового дайджеста.

Этот пакет содержит необходимые для развёртывания исходники и проверки.
Локальные данные аккаунтов, образцы писем и диагностическая история
разработки в пакет не включены.

## Google Календарь

Основной календарь Google подключается отдельно через OAuth с доступом только
на чтение. Защищённая страница `/settings/google` сохраняет разрешение на
постоянном диске; источник активируется после проверки выбранного аккаунта.
До авторизации действующие источники работают без изменений.

События Google включаются в дайджест. Для обычных событий push назначаются
накануне в 09:00 и за час до начала; для событий на весь день — накануне
и в день события в 09:00. Дни рождения сохраняют своё правило, а ночные push
переносятся на 07:00 МСК. Подключение чтения не предоставляет кнопок изменения
Google-событий. Требования к авторизации и проверке описаны в
[google-calendar.md](docs/google-calendar.md). Наличие кода не подтверждает
подключение реального аккаунта или установку обновления на Render.
